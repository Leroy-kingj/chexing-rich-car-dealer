## tt12 修复（三个问题仍存在的真正根因）★关键
- 用户反馈 tt11 上线后三大问题**依旧**：①登录页 TapTap 登录无法用、跳过登录未隐藏；②游戏内广告不看直接给奖；③游戏内分享提示不可用（平台自己分享可用）。
- **真正根因（前两轮误诊为"检测时机/const笔误"）**：`chexing-sdk.js` 的 `isTapEnv` getter 与 `tapCall()` 都调用了 `_isTapEnv()`，但**该函数从未定义** → 每次环境检测都抛 `ReferenceError`，整条初始化链崩溃：`boot()` 的 `isTapEnv` getter 抛错 → `initTapEnv()` 永不执行 → 跳过登录不隐藏；`tapLogin`/`ttShareToTapTap` 的 `isTapEnv` 检查抛错 → 功能失败；广告 `!isTapMiniGame` 分支直接走模拟发奖。这比"tap 注入时机"更根本——代码里引用了不存在的函数。
- 叠加问题：`tap` 检测只查裸 `typeof tap`，未覆盖 `window.tap`/`GameGlobal.tap`/`globalThis.tap`；官方文档明说真机小游戏**无 window、全局对象是 GameGlobal**，tap 异步注入。
- 修复（tt12，已同步 h5-build，**未上传**——按用户规则等下令"上传"）：
  1. 删除全部 `_isTapEnv()` 调用；getter 改为 `isNative || _refreshTap()!=null`（`_refreshTap` 自愈合）。
  2. `tap` 检测改**多源健壮探测**（window.tap/GameGlobal.tap/globalThis.tap），缓存到 IIFE 变量 `tap`；导出 getter 每次访问即时刷新。
  3. 轮询延长到 ~12s，注入后触发 `onTapReady` 回调。
  4. 全局挂载不假设 window 存在（多目标 window/globalThis/GameGlobal/self）；`boot()` 用安全 `CX` 引用防 SDK 缺失整段崩溃。
  5. `showRewardAd` 分支基于 `isTapMiniGame` 判断（不再误用 `typeof tap`）。
- Node 仿真验证：tap 异步注入 globalThis 后 `isTapEnv` 自动 true、`platform=taptap-h5`、login 正确走到 `tap.login()`。
- 待：用户说"上传"后我 `upload_h5_game`（触发审核）。仍待用户给激励视频 adUnitId 才能真播广告。
