## 2026-07-24 第29轮 — 修复默认五菱宏光S不显示在第1车位

### 需求
默认拥有的五菱宏光S(id=83)应停在第一个车位(spot 0)，但车位上不显示，车库却显示"已停"。

### 根因（关键 bug）
`mk(carId, loc, spotIdx)` 里 `spotIdx: spotIdx||-1` —— 传入 spotIdx=0 时 `0||-1` 结果为 `-1`（JS 中 0 是 falsy）。
- defaultState 调用 `mk(83,'spot',0)` → 实际 spotIdx 被错设成 -1
- `instAtSpot(0)` 按 `spotIdx===0` 查不到 → 车位0渲染成空
- 车库按 `loc==='spot'` 判定 → 显示"已停"
- 同样 bug 会影响任何停到 0 号车位的车（freeSpotIdx 可返回 0）

### 修复
1. `mk` 改为 `spotIdx:(spotIdx==null?-1:spotIdx)`，正确保留 0
2. `load()` 末尾加一次性迁移：扫描 loc==='spot' 且 spotIdx<0 的 inst，放到第一个空闲 unlocked 车位（避免冲突），无空闲则放 0

### 修改文件

## 2026-07-24 第63轮 — 收益进度收取后不重置（根因：重复逻辑漏改，已重构）

### 用户报告
车库的车子收取收益后，收益进度没有重置。强调"这个问题修过三次了，为什么会反复出现"。

### 根因（结构性）
进度条数据源是 `inst.accrued`。"收取收益+归零进度"的逻辑被复制粘贴进 4 个函数：
- collectInst(L3452)、collectAll(L3460)、recallCar(L3518)、parkCar(L2852)
"从好友家取回车辆"的 `recallFromFriend`(L2873) **从未重置 accured**——它是后加的"停好友家"功能，不在"收车"心智模型内，每次修都只补正在测的那条路径，唯独漏它。
→ 车从好友家取回时，原显示的"可收取"收益既没发放也没归零，带着旧 accrued 进车库；下次出车进度条从旧值起跳 → 表现为"进度没重置"。这就是反复出现的原因：**逻辑重复、无单一数据源**。

### 修复（app.js）
新增唯一函数 `settleAccrued(inst)`（L3451）：`if accued>0 → S.dollars += floor(accrued); S.stats.earned += amt; inst.accrued = 0; return amt;` 否则 return 0。
5 条路径全部改为调用它：
- collectInst：替换为 `const amt = settleAccrued(inst);`（保留 accrued<=0 提前 return 守卫）
- collectAll：`if(inst.loc==='spot'){ total += settleAccrued(inst); }`
