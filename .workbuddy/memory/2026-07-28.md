| `.pc-body` justify-content | center | **flex-start** | 内容从顶部排列 |
| `.pc-img-wrap` 尺寸 | min:85×120 | **固定140×90 + flex-shrink:0** | 定位基准稳定 |

| `.pc-car-name` | max-width:100% | **max-width:150px + flex-shrink:0** | 确保不被压缩 |

## 好友车位罚单：停留时间动态更新+30分钟门槛 (本地修改，未推送)

用户反馈（第6-7次修）：好友专属车位停留时间不动态变化；30分钟内仍可点开罚单。
### 根因
`updateParkGridsLite()` 中好友车位面板仅在**签名变化**时才调 `refreshFspotGrid()` 重建DOM。签名只包含 unlock/parkerUid/ticketed 三种结构性变化，不含时间——所以停留时间文本和按钮状态在两次结构变化之间完全冻结。

### 修复
新增 `_updateFspotTimes()` 函数（仿 `_updateParkNumbers` 模式）：
1. **每秒遍历所有 `.park-card[data-fspot]`**，找到停着车的好友
2. **动态计算 `parkedMins`**（基于 `parkedAtTs` 实时推算），更新 `.fspot-park-time` 文本
3. **动态切换按钮状态**：
   - 已贴单 → 灰色"已贴单" disabled
   - `parkedMins >= 30` → 绿色"开罚单"可点击
   - `parkedMins < 30` → 倒计时 disabled（如 "12:35"），数字每秒递减
4. **智能 DOM 替换**：仅按钮状态实际变化时才 `outerHTML` 替换，倒计时状态只改 `textContent`
5. `updateParkGridsLite()` 的 else 分支从空改为调用 `_updateFspotTimes()`

### 修改文件
- app.js: 新增 `_updateFspotTimes()` (~60行)；`updateParkGridsLite()` 加 else 分支
