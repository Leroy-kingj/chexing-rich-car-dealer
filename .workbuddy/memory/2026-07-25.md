## 老号三问题共同根因定位与根治 (→w, 18:45)

### 用户现象
老号（脏存档）同时出现：①无法招募员工 ②收取车辆收益不重置 ③兑换刀币看广告不消耗次数；清档新号一个都没有。

### 共同根因
老号核心字段结构损坏，而 `load()` 的字段归一化覆盖不全 + `_uid` 计算对非数组无防御：
1. **无法招募**：老号 `S.employees` 非数组（如 null）→ `S.employees.push/.length` 抛错（旧代码无防御；当前 v4 迁移只在 S.v<4 跑，老号 v 高被跳过）
2. **收益不重置**：老号 `S.inst[].accrued` 缺字段 → `tick()` 里 `inst.accrued = Math.min(undefined+inc, cap)` = **NaN** → 经济污染、进度永不正确（load 完全没归一化 inst）
3. **兑换不消耗**：老号 `S.exch` 非对象（数字）→ 旧代码 `S.exch.count++` 抛错（当前已归一化）

**关键崩溃点**：`load()` 末尾 `_uid = S.inst.length + S.employees.length + 200`（line 362）当 `S.employees` 非数组时抛 `Cannot read properties of null (reading 'length')` → load 崩溃返回 false → `if(!load()) S=defaultState()` 把老号覆盖成新号（之前测试假象的来源）。

### 修复（app.js load() 字段归一化段，在 _uid 计算前）
- `S.employees`：强制数组化，每项补 iid/name/networth/bonus/workCarIid/workEnd/hiredFrom/topHirerUid/lastMult
- `S.inst`：每项补 `accrued:0`（有限数字，关键防 NaN）、bonus/enhanceLevel/loc/spotIdx/count
- `S.friends`：数组化，净身价钳制 500~5000，补 timesHiredDay/timesHiredToday/employedBy
- `S.lastTick`：有限数字否则 now()（防 dt=NaN）
- `S.gacha`/`S.fc`/`S.stats`/`S.seven`/`S.taoche`/`S.rchAds`：对象/数组补齐（防 boot 崩）
- `_uid` 计算加防御：`(Array.isArray(S.inst)?...:0) + (Array.isArray(S.employees)?...:0) + 200`

## 订购按钮点击无反应修复 (→z, 19:08)

### 用户现象
订购界面点击消耗黄金（刀币）的按钮没有任何反应，无法购买车辆。

### 根因：CSS Stacking Context 层叠冲突
`renderOrder()` 生成的 DOM 结构中：
```
.mk-or-car-area (position: relative)  ← 父 stacking context
  ├── .mk-or-img (position: relative)     ← 子 stacking context | 先渲染
  │   └── .mk-or-buy > button             ← z-index:4（在 .mk-or-img 内）
  └── .mk-or-overlay-label (position:absolute; z-index:3)  ← 后渲染！覆盖在 .mk-or-img 整体之上！
```
`.mk-or-overlay-label` 和 `.mk-or-img` 是**兄弟节点**但属于**不同 stacking context**。虽然 overlay-label 的 z-index(3) < 按钮的 z-index(4)，但它们不在同一 stacking context 内比较 → DOM 后面的 overlay-label 绘制在 `.mk-or-img`（含按钮）**之上** → **点击事件被 overlay-label 拦截**。

### 修复
将 `.mk-or-overlay-label` 从 `.mk-or-car-area` 移入 `.mk-or-img` 内部，使它与按钮在同一个 stacking context（`.mk-or-img`）中：
- overlay-label: z-index:3（在下，左上角小标签）
- .mk-or-buy(按钮): z-index:4（在上，底部）

### 文件
- app.js `renderOrder()` line ~2437-2439：overlay-label 移入 .mk-or-img 内部（在 .mk-or-buy 之前）
- index.html：?v=20260724y → ?v=20260724z

## 黑车全身变黑修复 (→20260725b, 19:20)

### 用户现象

### 根因
全局 `.pc-car-img { mix-blend-mode: multiply }` 正片叠底混合模式将图片像素与深色卡片背景相乘：
- 黑色(0) × 背景色 = 纯黑（更黑）
- 深灰（窗户/轮毂）× 深色背景 = 几乎全黑 → **细节全丢**
- 白色高光 × 深色背景 = 被吃掉

### 修复
去掉全局 `mix-blend-mode: multiply` 和 `transform: scale` 放大：
- `.pc-car-img`：删除 `mix-blend-mode: multiply`
- `.gal-car-thumb`：删除 `mix-blend-mode: multiply` + `transform: scale(1.15)`
- AI生成车已用 `_cut.png` 透明底版本，不再需要 multiply 去白底；原始素材车显示完整图也比压黑好

### 文件
- css/style.css：.pc-car-img / .gal-car-thumb 去掉 multiply + scale

## 信息栏GUI入口闪烁修复 (→20260725f, 19:42)

### 用户现象

- 否则只更新 `#ib-asset`、`#ib-income` 两个数值 span 的 textContent → DOM 不重建，无闪烁
